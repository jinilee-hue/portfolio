# 포트폴리오 재구축 — 프로젝트 뷰어 설계

- 날짜: 2026-09-14
- 대상: 루트 `index.html` (배포되는 사이트)
- 형태: 히어로 + **한 번에 한 프로젝트**. 좌우 버튼·인덱스·키보드로 이동하고, 각 프로젝트 안에서 캡처와 상세 설명이 함께 놓인다
- 검토 시안: `_mockup-viewer.html` (승인 후 삭제). 초기 검토안 `_mockup-spread.html`은 폐기

## 1. 배경 — 지금 무엇이 문제인가

현행 사이트(시안 C "Screen Room")의 명제는 옳다. **실제 배포된 화면을 스톡 목업 없이 그대로 보여준다**는 것이고, 이게 이 포트폴리오의 존재 이유다. 문제는 그 명제를 받치는 규율이 없다는 것이다. 실측으로 확인한 문제는 다음과 같다.

1. **히어로가 비어 있다.** `min-height:92svh` + `justify-content:flex-end`로 상단 45%가 빈 검정이고 오른쪽 절반도 비어 있다. 여백이 아니라 미사용 공간으로 읽힌다.
2. **서체 하나가 무직이다.** Fraunces·Archivo·Pretendard 세 종을 로드하지만 한글에는 Fraunces 글리프가 없어 Pretendard로 폴백된다. 편집형 세리프 목소리가 한글 화면에 한 번도 등장하지 않는다.
3. **액센트가 전부를 강조한다.** 민트 `#2AF0CE`가 킥커·제목 강조·기여도 바·칩·타임라인·버튼·배지에 모두 쓰인다. 다 강조하면 위계가 사라진다. 2026년 레퍼런스가 "개발자 포트폴리오 클리셰"로 지목한 색군이기도 하다.
4. **13개가 같은 무게로 늘어선다.** 한 행에 번호·제목·요약·메타·기여도 바·태그 칩·상세 버튼 일곱 요소가 쌓이고, 그것이 13번 반복된다. 어느 것이 대표작인지 알 수 없다.
5. **화면이 작고 설명과 떨어져 있다.** 캡처는 곁다리 썸네일 크기이고, 케이스 스터디는 접힌 상세 안에 텍스트로만 들어가 있다. 어느 설명이 어느 화면 이야기인지 연결되지 않는다.
6. **데이터 시각화가 소음이다.** 타임라인이 210px를 쓰면서 라벨이 서로 붙어 읽히지 않는다.
7. **라이트 모드에서 밴드 1·2가 같은 색이다.** 밴드 1이 `--band: var(--bg)`이고 라이트 모드 `--bg`가 `#FAFAF8`, 밴드 2가 `#F4F2ED`라 구분이 사라진다.
8. **`og:image`가 404다.** `assets/og.jpg`를 가리키는데 파일이 없다.

```
히어로 (ink)         — 선언 + 지표 3개. 대표 캡처는 두지 않는다(바로 아래 패널과 중복되므로)
```

**폐기하는 것.** 이전 검토안의 "스프레드 7개 / 목록 6개" 분리, `.tl` 타임라인 섹션, "그 외 작업" 목록. 인덱스 줄이 목록과 타임라인의 역할을 모두 대신한다. 작업 기간의 전체 범위는 히어로 지표에 텍스트 한 줄(`2026.03 — 09 · 13개`)로 남긴다. 막대그래프를 유지하려면 실제 기간을 인코딩해야 하는데, 인덱스가 이미 그 정보를 제공하므로 중복이다.

**전 프로젝트가 같은 뷰어에 들어간다.** 케이스 스터디 유무는 진입 조건이 아니라 패널의 깊이를 정한다(§6). `featured`는 인덱스 정렬 우선순위로 쓴다.

## 5. 뷰어 내비게이션

### 구성

- 위치: 히어로 바로 아래, `position:sticky; top:0; z-index:40`. 밴드 색과 무관하게 항상 ink 계열 고정 — 패널 색이 바뀌어도 내비게이션은 같은 자리에 같은 모습으로 있어야 한다
- 좌: `작업 02 / 13` 진행 표시 (모노)
- 중: 인덱스 13개. `번호 + 제목`. 가로 넘침은 `overflow-x:auto`, 스크롤바는 숨기고 현재 항목을 `scrollIntoView`로 끌어온다
- 우: 이전 / 다음 버튼. 양 끝에서 `disabled`

### 동작

| 입력 | 결과 |
|---|---|
| 인덱스 클릭 | 해당 프로젝트로 |
| 이전 / 다음 버튼 | 순차 이동 |
| 인덱스에 초점이 있을 때 ← → | 인덱스 이동 (ARIA 탭 패턴) |
| 모바일 스와이프 (60px 이상) | 순차 이동 |
| `#<id>` 해시로 진입 | 해당 프로젝트를 열고 시작 |
| 이동 시 | `history.replaceState`로 해시 갱신 (뒤로가기 이력을 오염시키지 않는다) |

**시안에서 고칠 것:** 시안은 `document` 전역에서 ← → 를 가로채는데, 가로 스크롤이 필요한 상황과 충돌하므로 제거한다. 키보드 이동은 인덱스(탭 목록) 안에서만 처리하고, 그 밖에서는 눈에 보이는 이전/다음 버튼으로 이동한다.

### 접근성

- WAI-ARIA 탭 패턴을 따른다: 인덱스는 `role="tablist"`, 각 항목은 `role="tab"` + `aria-selected`, 패널은 `role="tabpanel"` + `aria-labelledby` + `tabindex="0"`
- 시안은 `aria-current`를 썼는데 `aria-selected`로 교체한다
- 이동 후 초점을 패널 제목으로 옮기지 않는다(스크롤 위치가 튄다). 대신 패널을 `tabindex="0"`으로 두어 Tab 한 번에 도달하게 한다
- 자동 회전 없음 → 정지 버튼 불필요
- `prefers-reduced-motion: reduce`에서 `scroll-behavior:smooth`와 호버 트랜지션을 해제

### 검색·AI 크롤러

숨긴 패널도 **HTML 소스에는 그대로 둔다**(`hidden` 속성만 부여). 이 사이트는 리크루터가 ChatGPT·Perplexity에 물어보는 경우를 대비한 AI 가독성 레이어(`llms.txt`, JSON-LD, `sitemap.xml`)를 명시적으로 두고 있으므로, DOM에서 제거하면 그 의도가 무너진다. JSON-LD `ItemList`는 현행처럼 13개 전부를 담는다.

### 인쇄

`@media print`에서 뷰어 바를 감추고 모든 패널을 펼친다.

```css
@media print{
  .vbar{display:none}
  .panel[hidden]{display:block !important}   /* [hidden] 의 UA display:none 을 되돌린다 */
}
```

## 6. 프로젝트 패널

### 6.1 표제부 (`phead`)

2단(1.55 / 1). 좌: `01 / 13` 번호(모노) → 킥커(모노, 액센트) → 제목 → 요약. 우: 기간 · 역할 · 기여 범위.

**시안에서 고칠 것:** 기여 범위 범례가 좁은 우측 칼럼에서 네 줄로 흩어진다. 바 아래 한 줄로 압축하고(`기획 30 · 디자인 40 · 개발 25 · 검증 5`), 넘치면 바만 남기고 범례는 `title` 속성으로 옮긴다.

### 6.2 화면 블록 (`screen`) — 이 설계의 핵심

캡처 하나당 블록 하나. 캡처(7)와 설명(4)을 좌우로 놓고, **블록마다 좌우를 반전**해 리듬을 만든다.

```
[ 캡처 + figcaption ]        [ 이 화면에서 — 설명 문단 ]
                             [ 번호 붙은 화면 주석 목록 ]

[ 설명 ]                     [ 캡처 + figcaption ]   ← 반전
```

- `figcaption`은 모노로 실측 뷰포트를 적는다: `Desktop 1440×900 — 실제 배포 화면 캡처`. 뷰포트를 밝히는 것이 "목업이 아니다"의 증거다
- 첫 블록 설명 = `concept` (없으면 `summary`), 주석 목록 = `flow`
- 둘째 블록 설명 = `intent`
- `shot_long`인 4개는 고정 높이 프레임 안에서 페이지가 실제로 흐르게 한다

### 6.3 화면별 설명 필드 (신규, 선택)

"화면에 대한 상세 내용"을 캡처와 1:1로 맞추려면 캡처마다 쓴 문장이 필요하다. 현재 데이터에는 없다.

- `data/overrides.json`에 선택 필드를 추가한다:
  ```json
  "shot_notes": { "desktop": {"ko":"…","en":"…"}, "tablet": {"ko":"…","en":"…"} }
  ```
- `assets/shared.js`의 `pick()`에 한 줄 통과 추가: `shotNotes: p.shot_notes || {}`
- **폴백을 두어 지금 당장은 아무것도 쓰지 않아도 된다.** `shot_notes`가 없으면 §6.2의 `concept`/`intent`를 쓴다. 나중에 캡처별 문장을 쓰면 그 자리를 대체한다

이것이 이 설계에서 `assets/shared.js`를 건드리는 유일한 지점이다. 로더의 다른 부분과 `scripts/`는 그대로 둔다.

### 6.4 결정 · 마무리

- `decisions`가 있으면 2단 그리드로. 각 항목은 모노 번호 + 문단
- `stack`은 모노 낮은 무게로. 없으면 블록 생략
- 마무리 줄: 태그(모노 아웃라인) + `화면 열기 ↗`(→ `live || repo`)
- **빈 필드는 블록 자체를 렌더하지 않는다.** 제목만 남은 빈 섹션을 만들지 않는다

### 6.5 패널 깊이 두 종

| | 케이스 보유 (7개) | 케이스 없음 (6개) |
|---|---|---|
| 표제부 | 전체 | 전체 |
| 화면 블록 | 2개 (설명 + 주석) | 1~2개 (캡션만) |
| 의도·컨셉·결정·스택 | 있는 것만 | 없음 |
| 분량 | 약 2,900px | 약 1,400px |

인덱스에서 두 종을 구분 표시하지 않는다. 짧은 패널도 캡처와 요약은 온전하고, 표시를 붙이면 절반이 "덜 중요한 것"으로 낙인된다.

## 7. 디자인 토큰

### 밴드 (절대값 · 컬러 스킴과 무관)

| 밴드 | 배경 | 전경 | 액센트 |
|---|---|---|---|
| ink | `#0A0A0A` | `#F2EFE9` | `#E0754A` |
| paper | `#F1EDE4` | `#16140F` | `#A6421F` |
| warm | `#241A14` | `#EFE8DF` | `#E88C56` |

히어로와 뷰어 바는 ink 고정. 패널은 인덱스 순서에 따라 paper → warm → ink 순환. 프로젝트를 넘길 때 배경이 바뀌어 "다른 작업으로 넘어왔다"는 신호가 된다.

**결정: 밴드 색은 `prefers-color-scheme`에 따라 바꾸지 않는다.** 밴드가 전폭이라 뒤에 보이는 것이 없고, 밴드 색을 `--bg`에서 파생시킨 것이 라이트 모드 충돌(문제 7)의 원인이었다. 절대값으로 고정하면 그 문제가 구조적으로 사라진다. 대가는 라이트 모드 사용자도 어두운 히어로를 본다는 것인데, 의도된 편집물로서 받아들인다.

시안에서 `warm #1A1512`가 ink와 너무 가까웠다. 위 표는 warm을 `#241A14`로 벌린 값이다. 구현 시 인접 밴드의 명도차를 재확인한다.

### 타이포 — 3종 → 2종

| 역할 | 서체 |
|---|---|
| 표제·본문 | Pretendard Variable (600/700/800) |
| 라벨·숫자·메타·태그·캡션 | IBM Plex Mono (400/500), `letter-spacing:.09em`, 대문자 |

Fraunces 제거(한글에서 무직). Archivo 제거(모노가 라벨 역할을 더 잘 하고, 레퍼런스가 말한 "제작 소프트웨어 라벨" 질감을 준다 — B 시안에서 이미 검증). 남는 두 종은 **둘 다 실제로 일한다.** 숫자에는 `font-variant-numeric: tabular-nums`.

### 액센트 사용 규칙

액센트를 쓸 수 있는 자리를 다음으로 **제한**한다. 그 외에는 전경색 투명도로 위계를 만든다.

- 킥커 텍스트
- 현재 선택된 인덱스 항목 (배경)
- 호버·활성 상태
- `화면 열기` 버튼 배경
- 기여도 바 — 4색이 아니라 **액센트 한 색의 투명도 4단** (1 / .72 / .46 / .24)
- 화면 주석 목록의 번호

기여도 바의 톤온톤은 `poly-dashboard` 프로젝트 자체의 원칙("색을 고르는 결정을 없앤다")과 같은 논리다.

### 레이아웃

- 밴드는 화면 전폭. 좌우 padding이 `.wrap` 정렬선을 재현한다:
  `padding-inline: max(var(--pad), calc(50% - 750px + var(--pad)))`
- `vw`가 아니라 `%`를 쓴다 — `vw`는 스크롤바 폭을 포함해 다른 섹션과 몇 px 어긋난다(이번 작업에서 실측 확인)
- `1000px` 미만에서 화면 블록은 1단으로 접힌다(캡처 → 설명 순)

### 기기 프레임

CSS로 그린다(이미지 요청 0). 두 가지를 반드시 유지한다.

- `.frame`에 `display:block` — `<span>`이라 없으면 인라인으로 남아 `width`/`padding`이 먹지 않고 블록인 `.shot`이 프레임을 뚫는다(이번에 고친 버그)
- 베젤 색은 전역 `--bg`가 아니라 **놓인 밴드 색**과 섞는다

| 인덱스 정렬 | `featured` 우선, 그 안에서 기존 정렬 |
| 인덱스 라벨 | `title` |
| 표제부 | `title`, `kicker`, `summary`, `period`, `role`, `contribution` |
| 캡처 | `shots[]` (`device`, `src`, `long`) |

| 링크 | `live \|\| repo` |
| 패널 깊이 | `hasCase` |

## 9. 성능

한 번에 한 패널만 보이므로 현행보다 유리하다.

- 숨은 패널의 이미지는 `loading="lazy"`로 두면 표시될 때까지 요청되지 않는다. 초기 요청은 첫 패널의 캡처 2개뿐
- 첫 패널의 데스크톱 컷만 `fetchpriority="high"` (LCP 대상), 나머지는 `lazy` + `decoding="async"`
- `onerror`로 실패한 컷을 제거하는 현행 방어 유지
- 배포 후 Lighthouse로 LCP/INP/CLS 확인

## 10. 접근성 (패널 내부)

- 이미지 `alt`에 기기와 "실제 배포 화면" 명시(현행 계승). 프레임은 장식이므로 구조를 노출하지 않는다
- 캡처는 `<figure>` + `<figcaption>`으로 묶어 캡션이 프로그램적으로 연결되게 한다
- 액센트 대비를 구현 중 수치로 검증: 본문 4.5:1, 큰 텍스트·UI 3:1 이상. 특히 paper 밴드의 `#A6421F`와 `화면 열기` 버튼(클레이 배경 + 밴드색 글자) 조합
- 이동 버튼에 `aria-label` 부여(시안 반영됨)

## 12. 검증 방법

헤드리스 Chrome으로 좌표와 색을 실측한다(이번 작업에서 유효성을 확인한 방법).

1. **정렬**: 패널 콘텐츠 좌측 시작점 == 히어로 == 원칙 섹션. 1920 / 1400 / 900 폭에서 확인
2. **전폭**: 밴드 `getBoundingClientRect().left == 0`, `width == clientWidth`, 가로 스크롤 없음
3. **뷰어**: 13개 인덱스 렌더, 이전/다음이 양 끝에서 `disabled`, 해시 진입이 해당 패널을 열고, `aria-selected`가 하나만 `true`
4. **프레임**: 베젤 두께 좌우 대칭, `display:block` 적용 확인
5. **대비**: 밴드 3종 × 액센트·전경 조합의 명도비 계산
6. **크롤러**: 숨은 패널의 제목·요약이 `--dump-dom` 출력에 존재
7. **인쇄**: `@media print` 에뮬레이션에서 13개 패널이 모두 펼쳐짐
8. **성능**: 초기 로드 이미지 요청 수가 2개인지 확인

## 13. 미해결

- 원칙 섹션(`같이 일할 때 알아두면 좋은 것들`)은 구조를 유지하고 타이포만 새 체계를 적용한다. 뷰어 리듬에 맞춘 재구성은 이번 범위에서 제외
- `shot_notes` 문장 작성은 사람의 일이며 배포를 막지 않는다(폴백이 있다). 대표 프로젝트부터 점진적으로 채운다
- `summary`가 빈 4개 프로젝트는 저장소 설명으로 폴백되는데, 뷰어에서 표제부가 커진 만큼 직접 쓰는 편이 낫다
